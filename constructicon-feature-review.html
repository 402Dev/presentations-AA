Feature 01 / Form

The Component Registry

A declarative list of the components a construction needs before any word-order template is applied.

Category: Form
Clear definition
The Component Registry asks one first question: which parts must be present before we decide how they are arranged on the surface?
One compact example
[Subj_NP] [Verb_Action] [Poss_Pron] [way] [Obl_Path]
Name the parts first; decide clause type and word order later.
Central question
Which components exist before ordering begins?
Fixed anchor
A hardcoded word
Its lexical form is fixed across instantiations, such as way, er, or ra.
Open slot
A variable blank
It accepts material constrained by labels such as Subject_NP, Object_NP, or Verb.
Feature 01 / Examples + Utility

Same feature across constructions

The component inventory stays stable even when each language uses a different surface pattern.

English
The Way-Construction
[Subj_NP V_Action Poss_Pron way Obl_Path]
“He hacked his way through.”
Anchor way
Open slots Subject, Verb, Poss, Path
Dutch
Evaluative Frame
[Subj_NP zien er Adj uit]
“Het ziet er goed uit.”
Anchors zien, er, uit
Open slots Subject, Adjective phrase
Farsi
Specific Accusative
[Subj_NP Obj_NP ra V_Trans]
“Ali ketab ra khund.”
Anchor ra
Open slots Subject, Object, Verb
Constructicon payoff
Store the component inventory once, then compare constructions by required parts rather than only by surface order.
Query payoff
Search by schema signature first, then ask how each construction linearizes that component set.
