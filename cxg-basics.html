What Speakers Have to Know

(Based on Martin Hilpert)

  • Know words and vocabulary.
  • Understand how to combine words into phrases and sentences.
  • Apply the correct endings to words (morphology).
  • Comprehend newly coined or unfamiliar words.
  • Recognize that intended meaning sometimes differs from the literal words said.
  • Adapt language use across different contexts and situations.
  • Know and understand idiomatic expressions.

Why not stick with dictionary-and-gramar model?

-> The view where we assume the knowledge of language is comprised of knowing words and the rules how to combine them into phrases fails when we consider idiomatic expressions such as “break a leg”, “as … as”, BIG MESS construction.

Enter Construction Grammar (CxG)

Construction Grammar argues that every observed linguistic utterance is an instantiation of one or more grammatical constructions.

A construction (cxn) refers to a form-meaning pair.

Lets define some terms

  • Form: The structural shape (words, grammar, sounds).
  • Meaning: The literal concept or information conveyed.
  • Function: The speaker's real-world intent or goal (e.g., a command, a joke).
  • Construct: The actual, physical utterance produced in the real world.

1. Morpheme Level

1
Morpheme

(The smallest unit)

Example: The plural marker -s

  • Form: The suffix -s (or -es).
  • Meaning: "More than one" or multiplicity.
  • Function: To quantify a noun for the listener.
  • Construct: The word “bugs” (in the utterance, "There are bugs in my code").

2. Word Level

2
Word

Example: The word Water

  • Form: The noun water (phonetically: /ˈwɔːtər/).
  • Meaning: The chemical substance H₂O.
  • Function: To identify or refer to the physical liquid in a discussion.
  • Construct: The spoken word “water” (in the utterance, "Pass me the water").

3. Fixed Idiom Level

3
Fixed Idiom

(Words locked together)

Example: Kick the bucket

  • Form: Verb (kick) + Definite Article (the) + Noun (bucket).
  • Meaning: To die. (Notice how the meaning of the whole is not the sum of its parts).
  • Function: To soften the blow of discussing death (euphemism) or add dark humor.
  • Construct: "My old laptop finally kicked the bucket yesterday."

4. Partially Filled Idiom

4
Partially Filled

(Some fixed words, some open slots)

Example: Drive [Someone] Crazy

  • Form: Verb (drive) + Object Slot (X) + Adjective (crazy).
  • Meaning: To cause someone to experience extreme annoyance or distress.
  • Function: Expressing frustration or dramatic hyperbole to get sympathy.
  • Construct: "This missing comma is driving me crazy."

5. Abstract Syntax Level

5
Abstract Syntax

(Pure structure, no fixed words)

Example: The Ditransitive Construction

  • Form: Subject + Verb + Noun Phrase 1 (Recipient) + Noun Phrase 2 (Theme).
  • Meaning: "X causes Y to receive Z" (Transfer of possession).
  • Function: To quickly highlight the recipient of an action without using prepositions (like "to" or "for").
  • Construct: "She handed him the dataset."

Feature: The Component Registry

Anchors & Slots — The Root Array

Schema location: Whole Construction. A declarative list of every node required by the construction—defined before any word-order template is applied.

Database Data Types

component_registry [Array<Object>]
The root array. Each item is one node of the construction.
node_type [Enum]
FIXED_ANCHOR or OPEN_SLOT
expected_value [String]
Anchor: literal lemma — e.g. “zien”. Slot: syntactic category — e.g. Noun_Phrase.
node_id [UUID / Integer]
Unique ID so downstream rules (word-order, agreement) can target this node precisely.
FIXED_ANCHOR
A hardcoded word
Lexically fixed; its presence and form do not vary across instantiations of the construction.
OPEN_SLOT
A variable blank
Accepts any lexical item that satisfies the declared syntactic category constraint.

Component Registry — Utility

General CxG Organization
Defines the API Contract
The registry tells your LLM parser exactly how many JSON keys to extract. If the registry declares 5 nodes, the parser must return 5 nodes — no guessing, no key dropping.
Calculates Schematicity on the Fly
No dedicated “abstractness” column needed. Query the ratio of OPEN_SLOT to FIXED_ANCHOR in the array instead.
Topology-Agnostic
The same registry can be inherited by different word-order templates — Main Clause, Subordinate, Question — without duplicating lexical data.
Pedagogical Engine
Dynamic UI Generation
The front-end reads the Component Registry and dynamically renders exactly the right number of drag-and-drop blanks and pre-filled text blocks for “Flash Card 2.0” exercises — straight from the schema, with zero hardcoding.

Feature: The Topological Mapping Matrix

Spatial Sequencing — Where a Node May Legally Exist

Schema location: Constituent Slot level, governed by the overarching Topological Template. Decouples existence (Component Registry) from position (this matrix).

Database Data Types

topological_zone [String / Enum]
The designated spatial field — e.g. Pre-Verbal, Mittelfeld, Terminal_Anchor.
positional_rigidity [Enum]
ABSOLUTE — node occupies an exact, hard-indexed position (e.g., English subject).
FLEXIBLE_INTRA_ZONE — node can scramble with others inside the same zone (e.g., Dutch Mittelfeld).
adjacent_constraints [Array<String>]
Optional. Forces physical adjacency regardless of zone — e.g. must_precede: Slot_ID_2.
ABSOLUTE
Fixed position
The node occupies exactly one slot in the linear string. Scrambling this node is a grammatical violation.
FLEX_INTRA_ZONE
Free inside a zone
The node can reorder relative to sibling nodes within its zone without violating the construction.

Topological Mapping — Utility

General CxG Organization
Separation of Concerns
Decoupling existence (Component Registry) from position (this matrix) avoids combinatorial explosion. No separate row is needed for every legal scrambled variation of a Farsi sentence.
Dimensionality Reduction
Abstract topological templates — e.g., the Dutch V2 rule — are stored exactly once and inherited by thousands of distinct lexical frames, creating a highly normalised relational structure.
LLM Parsing & Analysis
Algorithmic Error Diagnosis
When a parser hits a syntax error, the matrix lets it isolate the variable and report precisely: “The required components are present, but a node violated its positional_rigidity constraint.”
Pragmatic Feature Extraction
In flexible-zone languages (Farsi, Russian), the parser validates the syntax via the matrix, then compares the actual word order to the default to extract pragmatic metadata — e.g., tagging a fronted node as “Topicalized Focus.”

Feature: Slot Elision Profile

Schema Mapping (Null Instantiation)

Applies at the Constituent Slot level. Not a global feature—each individual slot within a construction must define its own elision rules.

Database Data Types Needed

elision_allowed [Boolean]
Can this specific slot be empty in the physical text?
elision_type [Enum]
E.g. Lexical, Grammatical, Pro-Drop, Conversational.
recovery_method [Enum/String]
How the parser infers missing data (Morphology, Context, Hardcoded Default).

Multilingual Examples

English (Imperative)
"Push it to main." → Target: Subject Noun Phrase
elision_allowed: TRUE  |  type: Grammatical  |  recovery: Default ("You")
Farsi (Pro-Drop)
"Ketab ro khundam." → Target: Subject Noun Phrase
elision_allowed: TRUE  |  type: Pro-Drop  |  recovery: Verb Suffix
Dutch (Vorfeld Deletion)
"Heb ik al gezien." → Target: Vorfeld (Topic)
elision_allowed: TRUE  |  type: Conversational  |  recovery: Context

Organisational Utility & Construct-i-con Case

The DRY Principle

General CxG Organization

Solves Combinatorial Bloat
Without this, a database stores two separate rows for every transitive verb in pro‑drop languages. Moving elision to the slot level collapses variations into a single, elegant topological row.
Schema Stability for AI
Forces the LLM parser to output uniform, fixed‑dimension JSON. Instead of dropping missing keys, the LLM outputs NULL values tagged with the exact Elision Reason.
Pedagogical Engine

The Construct-i-con Use Case

Fluency vs. Grammar
Native speakers omit words; textbook learners over‑articulate. By logging Elision Profiles, the pedagogical engine tracks a user's pragmatic mastery.
Targeted Feedback
If a student inputs "Yo quiero el agua", the engine queries the Spanish Transitive frame, sees the Subject slot has elision_allowed: TRUE, and actively coaches on natural speech patterns.
